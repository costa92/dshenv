# DSH 配置参考

- 日期：2026-10-08
- 依据：DSH 源码 `deepseek-harness` 提交 `5badb15009`（0.2.1-alpha.1），路径相对该仓库根；本机 `~/.dsh`
- 用途：dshenv 设计所依赖的 DSH 配置事实。dshenv 自身的设计与待办见 [设计文档](2026-10-08-设计文档.md)
- 注意：dshenv 目前放行的 DSH 版本族是 `0.1.7`、`0.2.0`（`src/dsh/version.ts`）；本文依据的 0.2.1-alpha.1 仍需 `--allow-untested-dsh`。版本间差异见第 5 节

## 1. 主目录与 Profile 的解析

- **DSH 主目录**：DSH 没有对应的命令行参数，顺序是插件 `config.dshHome`（只有 credentials-local、skill-filesystem、agent-instructions 等少数插件支持）> `DSH_HOME`（空白视为未设置）> `~/.dsh`，支持 `~` 展开（`packages/util/home-paths/src/index.ts:79-91`）。`DSH_*` 不能写在 `.env` 里。dshenv 的 `--dsh-home` 只决定 dshenv 自己操作哪个目录，调用 DSH 时通过 `DSH_HOME` 传下去。
- **Profile**：必须用 `--profile <name>` 或裸名 `dsh <name>` 指定，没有默认值，也没有选择 Profile 的环境变量（`apps/cli/src/args.ts:168-179,201-205`）。目录为 `$DSH_HOME/profiles/<name>`，名字不能含 `/`、`\`，也不能是 `.`、`..`、`node_modules`。
- **出厂模板**：`web`、`headless`、`sdk`、`sdk-minimal`、`acp`，首次使用时自动初始化。其他名字要用 `--from-default-profile <模板>` 或 `dsh plugin --profile <name> …` 先建好，后者只带 `@deepseek-ai/dsh-base`（`packages/boot/app-boot/src/profile.ts:179-213`）。`desktop` 保留给 Electron：npm 版 `dsh` 不接受这个名字（不区分大小写），Desktop 自带的 CLI 可以对它执行 `dsh plugin`（`apps/cli/src/args.ts:83-87,143,195`）。

项目目录没有补丁层（`profile-context.ts:62-75` 不读 cwd 下的任何文件），只能提供以下内容：

- `<cwd>/.env`：取启动目录，不是项目根；
- `.dsh/skills`、`.agents/skills`：项目根是从 cwd 往上找到的第一个含 `.git` 的目录，找不到就用 cwd；
- 项目根到 cwd 之间每一级目录里的 `AGENTS.md`、`CLAUDE.md`、`AGENTS.local.md`、`CLAUDE.local.md`。

MCP server、模型和 provider 都没有独立的配置文件，它们就是补丁里的行，例如每个 MCP server 是一个 `@deepseek-ai/dsh-mcp-client` 实例。

## 3. 生效顺序与补丁语义

生效顺序（后者覆盖前者，`packages/boot/app-boot/src/profile-context.ts:62-75`）：

```
bundle 补丁（按 dsh.profile.bundles 顺序，每个 bundle 可声明多个文件）
  → profiles/<p>/cordis.patch.yml
  → $DSH_HOME/cordis.patch.yml
  → 每个 --patch（按参数顺序）
  → DSH_TELEMETRY_DISABLED 非空且组合结果中有该行时，追加 { id: session-telemetry-otel, disabled: true }
```

各层先拼成一个列表再依次应用（`profile.ts:808-815`），所以后面的层可以修改或禁用前面 bundle 插入的行。

**补丁形式**（`vendor/include/src/index.ts:66-124`）：

- `insert: [行]`：追加到顶层末尾。带 `id` 时追加到该 group 的 `config` 末尾，目标不是 group 就警告并跳过。同一条里的其他键会被忽略。**没有** `before` / `after` 之类的位置键。
- `id + 其他键`：按 id 精确匹配，再执行 `target[key] = value`，**整体替换**同名字段，`config` 不做深合并。可以改任何字段，包括 `disabled`、`group`、`inject`、`isolate`。
- `name` 不会被写进目标，只用来断言：与目标的 name 不一致时警告并跳过整条补丁。
- id 索引会递归进入 group，因此可以直接定位 group 里的子行。新插入的行立即加入索引。id 重复时，补丁命中最后一个被索引的行。

**其他规则**：

- **没有删除操作**：关掉一行只能写 `disabled: true`，写 `disabled: false` 可以重新启用。父 group 被禁用时，子行一并失效。
- **匹配不到的 id 只警告**，不会让启动失败。以下情况会让启动失败：
  - 文件读取或解析失败、顶层不是数组、元素不是映射；
  - `--patch` 指定的文件不存在（bundle 补丁缺失或无法解析只会跳过该 bundle，见下条）；
  - 必需行激活失败（`agent-loop`、`webserver`、`modules`、`connection` 等）。
  
  Profile 层或全局层的文件不存在时，等于这一层为空。
- **bundle 失败不致命**：bundle 解析失败、读不到 manifest 或补丁、peer 版本不兼容且没有豁免时，跳过该 bundle，记入 `skippedBundles`，启动时打印一次。
- **YAML**：使用 `JSON_SCHEMA`，只多一个 `!!js` 标签。`!!js` 只在 `config`（递归）和 `disabled` 里求值，写在 `inject` 等字段里不会求值。求值环境可用 `process.env`、`dshHomePath`、`ctx.get(...)`。**没有 `${...}` 插值。**
- **路径**：`insert` 行的 `name` 若是绝对路径或以 `./`、`../` 开头，按**补丁文件所在目录**解析成 file URL；替换用的 `config` 值保持字面量。
- **空文件或只有注释的补丁文件会让启动失败**，必须写成 `[]`。热重载时文件无效只警告，并保留当前配置。
- **热重载**：由 base bundle 中的 `hmr` 行（`@deepseek-ai/dsh-hmr`，`disabled: !!js "!ctx.get('profileContext')"`）负责，监视 Profile 的 `package.json` 和两层补丁文件（`packages/boot/hmr/src/index.ts:329-350`）。bundle 补丁不监视，但每次重新组合时会重读；`--patch` 的内容在启动时就固定了，改了要重启（`apps/cli/src/profile-boot.ts:180-181`）。这一行被禁用或不存在时，改动要重启才生效。出厂模板中只有 `web` 默认热重载。dshenv 用 `--dump-config` 读取这一行来判断要不要提示重启（`src/dsh/hmr.ts`）。
  - 旧字段：0.1.6-alpha.1 及以前用 `package.json` 里的 `dsh.profile.patchReload: live | startup` 控制，0.1.6-alpha.2 起删除（git tag 可查）。
  - 本机现状（仅作记录）：`~/.dsh` 的 `web`、`headless` 两个 Profile 还带着这个字段；本机装的 `dsh` 是 0.1.5-rc.2，低于 dshenv 的门禁版本。
- **密钥**：配置里只写环境变量名（`apiKeyEnv`、`secretEnv` 等，schema 角色为 `credential-ref`）。值的解析顺序：启动环境 > `.credentials.yaml` > `<cwd>/.env` > `$DSH_HOME/.env`（`credentials-local/src/index.ts:5-10,553-567`）。
  - `.env` 拒绝启动类变量（`DSH_*`、`XDG_*`、`PATH`、TLS/CA 等）；代理变量只认 `$DSH_HOME/.env`。
  - MCP 行的 `env`、`headers` 是字面值，不是 `credential-ref`，是明文密钥最可能出现的位置。
- **校验入口**（都要带 `--profile`，三者互斥，`apps/cli/src/args.ts:119-179`）：
  - `dsh --profile <p> [--patch <文件>] --dump-config`：只做 YAML 组合，**不启动、不加载插件、不求值 `!!js`**。匹配不到的 id 以 `[层标签]` 前缀写到 stderr，不含遥测补丁。会写 Profile 目录：每次重写 `cordis.yml`，遇到已退役的 bundle 时改写 `package.json`。Profile 缺失时，出厂模板名会被创建，其他名字直接报错（`apps/cli/src/profile-boot.ts:167-172`、`packages/boot/app-boot/src/profile.ts:786-794`）。被跳过的 bundle 会以 `dsh: skipping profile bundle "<包>": <原因>` 写到 stderr。
  - `--dump-default-config`：只输出 bundle 层，不能与 `--patch` 一起用。
  - `--dump-config-schema`：会 import 每个插件模块并执行其顶层代码，只能对可信 Profile 运行，并且要加超时；收集不完整时退出码为 1。

## 4. 指定位置的 Skill 与 Plugin

**Skill**：DSH 自带的 `@deepseek-ai/dsh-skill-filesystem`（行 id `skill-filesystem`）按 rank 扫描一组根目录，可以在 Profile 补丁里加任意目录：

```yaml
- id: skill-filesystem
  config:
    customSkillDirs:            # 绝对路径；DSH 直接读取并监视
      - /data/dsh-resources/skills
      - !!js process.env.HOME + '/code/my-skills'   # 不展开 ~，相对路径按 cwd 解析
    includeDefaultRoots: false  # 可选：不再扫描项目根、用户根和内置根
```

| Rank | 来源 | 路径 |
|---|---|---|
| 100 | 项目 | `<项目根>/.dsh/skills` |
| 200 | 项目 | `<项目根>/.agents/skills` |
| 250 | 运行时 | runtime provider |
| 300 | 自定义 | `customSkillDirs` |
| 400 | 用户 | `<DSH_HOME>/skills` |
| 500 | 用户 | `~/.agents/skills`（或 `$DSH_AGENTS_HOME/skills`） |
| 600 | 内置 | `bundledSkillDir`，默认取 `$DSH_BUNDLED_SKILL_DIR` |

（`packages/skill/skill-filesystem/src/index.ts:36-40,166-177,245-264`；`packages/skill/skill/src/index.ts:24-28,78`）

- **重名**：同一作用域层内 rank 小的胜出；rank 相同时先比 provider 注册顺序，再比 provider 内部顺序（`customSkillDirs` 按列出顺序）。Agent preset 作用域层的同名 skill 直接胜出（`packages/skill/skill/src/index.ts:352,807-810`）。所以项目里的同名 skill 会盖过 dshenv 复制进 `<DSH_HOME>/skills` 的那份。
- **`customSkillDirs`** 只做 `path.resolve`，`~/x` 会被当成 cwd 下的相对路径，要写绝对路径或用 `!!js`。`!!js` 不能进团队 remote（dshenv `src/remote/snapshot.ts` 的 `assertNoJsExpressions`），这种条目只适合放本机 overlay；`pull` 不会把 `!!js` 条目自动放进 overlay，要手工移过去。
- **其他配置键**：`providerName`、`dshHome`、`agentsHome`、`bundledSkillDir`、`watch`（默认 true）、`watchUsePolling`、`watchFollowSymlinks`（默认 true）、`watchStabilityThresholdMs`、`watchPollIntervalMs`、`watchMaxProjects`（`packages/skill/skill-filesystem/src/index.ts:49-89`）。
- **团队与本机**：这是普通的 Profile 补丁。`pull` 收进清单，含本机绝对路径时写进本机 overlay；改 overlay 后 `apply --yes` 写回 DSH。
- **`includeDefaultRoots: false`**：`<DSH_HOME>/skills` 不再被扫描，而 dshenv 正是把 `envctl/skills` 复制到这里，所以要把它显式写进 `customSkillDirs`。这样挂上后 rank 是 300，而且 `.system` 子目录不再被跳过（`packages/skill/skill-filesystem/src/index.ts:254,257,727`）。显式写了 `bundledSkillDir` 时内置根仍会挂上。

| | `envctl/skills` | `customSkillDirs` 中的外部目录 |
|---|---|---|
| 内容由谁管 | dshenv：摘要、所有权、快照、回滚、团队 remote | 目录自己的 Git 仓库 |
| 如何到达 DSH | `apply` 复制进 `<DSH_HOME>/skills` | DSH 直接读取 |
| DSH 里的修改 | `pull` 收回 | 本来就是同一份文件 |
| `rollback` | 恢复 skill 内容 | 只恢复“扫描哪些目录”这项配置 |

外部目录的内容不进 dshenv 的摘要和快照：它们已由各自的仓库做版本管理。

**Plugin**：插件依赖装在 `profiles/<p>/node_modules`。bundle 包先从 DSH 安装目录解析，再从 Profile 解析；Profile 依赖中已装进 `profiles/<p>/node_modules` 的包走它自己的那份（`packages/boot/app-boot/src/profile.ts:16-19,535-540,706-717`）。从指定位置加载有两种方式：

```bash
dshenv install /data/dsh-resources/plugins/my-plugin -p web   # 登记为 local-link
dshenv apply --yes                                            # DSH 经 pnpm link: 指向该目录
```

- **`local-link`**：pnpm 记为 `link:<绝对路径>`（DSH 只把 `./`、`../` 补成绝对路径）。`apply` 记录源目录摘要，内容变了 `plan` 会提示更新。
- **`local-file`**：pnpm `file:` 协议复制一份安装，DSH 自己没有“复制安装”的功能。
- **接管与迁移**：`pull` 接管时，含本机路径的条目按规则写进本机 overlay；源目录在数据目录内时，`migrate` 会改写路径（设计文档 4.4 节）。
- **不推荐的写法**：补丁 `insert` 行的 `name` 直接写模块的绝对路径，也能加载，但不经过 pnpm 安装依赖，也不经过 dshenv 的插件管理。

## 5. 版本间差异（0.1.7 → 0.2.1-alpha.1）

依据 deepseek-harness 的 `docs/upgrade-guide/` 与 git tag 对比，只列与 dshenv 相关的部分。

- **invariants**：`sdk-minimal` bundle 删掉了 `invariants`、`session-invariant`、`agent-invariant`、`scope-invariant`、`agent-loop-invariant` 五行。包 `@deepseek-ai/dsh-invariants` 和所有 `<包>/invariant` 子路径也已删除。
- **schedule**：0.1.7 并没有 schedule bundle。`@deepseek-ai/dsh-experimental-schedule-bundle` 是 0.2.0-rc.1 加入的，0.2.1-alpha.1 又退役了。加载 Profile 时 DSH 会自动把它从 `dsh.profile.bundles` 里删掉（`packages/boot/app-boot/src/profile.ts:206-210,664-674`），dshenv 清单里若还声明着它，就会反复出现漂移。
- **默认行**：web-app 的 `schedule`、`ui-schedule` 改为默认启用。`time-context` 移到 `presets/*.patch.yml`，顶层对 `time-context` 的覆盖已经匹配不到。
- **新增行**：`otel`、`desktop-product-telemetry`、`product-analytics`、`ui-settings-session-log`，以及 `@deepseek-ai/dsh-tool-schedule`。
- **热重载**：不属于 0.2 的变化。`dsh.profile.patchReload` 在 0.1.6-alpha.2 就已删除，改由补丁组合里的 `hmr` 行控制。dshenv 的 `src/dsh/hmr.ts` 本来就是探测这一行，不需要改。
- **CLI**：没有增删参数。npm 版 `dsh` 仍拒绝 `--profile desktop`；0.2.1 起，Desktop 自带的 CLI 可以管理这个 Profile，前提是 Desktop 已经初始化过它。
